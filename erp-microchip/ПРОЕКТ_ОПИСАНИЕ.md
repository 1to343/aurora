# ERP-система управления производством микрочипов
## Полное описание проекта

---

## 1. ОБЩЕЕ НАЗНАЧЕНИЕ

Проект — рабочий прототип корпоративной информационной системы класса **ERP**
(Enterprise Resource Planning) для предприятия по производству микрочипов и
полупроводниковых изделий. Разработан по техническому заданию
`ТЗ_ERP_Производство_Микрочипов.docx`.

Система реализует **Этап 1** плана внедрения из ТЗ (ядро: авторизация, склад,
базовое производство) и расширена дополнительными модулями: логистика, чат,
живая симуляция производства и интерактивная 3D-визуализация дерева техпроцесса.

**Назначение системы:**
- Сквозное управление производственными процессами — от сырья до готового чипа.
- Полная прослеживаемость партий (lot traceability) на каждом этапе техпроцесса.
- Объединение подразделений (склад, производство, ОТК, логистика, персонал) в
  единую информационную среду.
- Повышение прозрачности, снижение брака, контроль складских остатков в реальном
  времени.

## 5. РОЛИ И ДОСТУП (RBAC)

Система поддерживает ролевую модель. Авторизация — JWT в cookie, все действия
пишутся в аудит-лог (пользователь, действие, объект, IP, время).

| Роль | Логин/пароль | Основные права |
|------|--------------|----------------|
| Администратор | `admin` / `admin` | Полный доступ ко всем модулям |
| Директор | `director` / `director` | Просмотр всех данных, отчётность, аудит |
| Технолог | `tech` / `tech` | Техпроцессы, маршруты, рецептуры |
| Оператор | `operator` / `operator` | Регистрация операций, приёмка/выдача |
| Начальник смены | `shift` / `shift` | Планирование смены, контроль WIP |
| Специалист ОТК | `qc` / `qc` | Контроль качества, статусы партий |
| Логист | `logist` / `logist` | Заказы, поставки, материалы |
| Механик | `mech` / `mech` | Учёт оборудования (заложено в модель) |
| Бухгалтер | `accountant` / `accountant` | Учёт затрат (заложено в модель) |

Доступ к API ограничен декоратором `require_roles(...)`; администратор имеет
доступ ко всему. Вкладка «Аудит» видна только администратору и директору.

## 6. ОПИСАНИЕ ВКЛАДОК

Каждая вкладка оформлена в единой тёмной теме, имеет вращающийся 3D-полиэдр
(hero-элемент, свой для каждой вкладки), декоративные боковые панели, цифровые
часы в шапке и плавные анимации.

### 6.1. ДАШБОРД (`/`)

Командный центр предприятия. Hero-полиэдр — большой медленный голубой икосаэдр.

**Содержимое:**
- **4 KPI-карточки** (обновляются в реальном времени, с эффектом свечения):
  - 📦 Выпуск за неделю
  - ⚠️ Средний % брака (краснеет при >3%)
  - 🔄 Активных партий
  - ⚙️ Средняя загрузка оборудования
- **5 графиков Chart.js:**
  1. *Выпуск по дням* — площадная диаграмма (area) за 14 дней с градиентной заливкой.
  2. *Процент брака* — линейный график за 14 дней с пунктирной линией нормы (3%).
  3. *Загрузка оборудования* — горизонтальные столбцы по 5 станкам, цвет по уровню
     (жёлтый <60%, голубой 60–85%, зелёный >85%).
  4. *Распределение по этапам* — кольцевая диаграмма (doughnut), данные из живой
     симуляции.
  5. *Запасы склада* — столбчатая диаграмма остатков, обновляется при пополнении.
- Кнопка «Обновить данные» с анимацией вращения иконки.

### 6.2. СКЛАД / WMS (`/`wms`)

Контроль складских запасов. Hero-полиэдр — зелёный куб.

**Live-блок (реальное время, из симуляции):**
- Таблица остатков 8 материалов с прогресс-барами заполнения.
- Автоматическое пополнение каждые 2–4 минуты (+50–200 шт.) с toast-уведомлением
  и зелёной flash-подсветкой изменённой строки.
- Поиск по материалам.
- Кнопка ручного пополнения с модальным окном.

**Вкладки операций (реальная БД):**
- **Остатки БД** — остатки в разрезе ячейки, партии, материала.
- **Приёмка** — регистрация поступления материала по лоту в ячейку, со сроком
  годности.
- **Выдача** — выдача в производство по стратегиям **FIFO** (по дате приёмки) или
  **FEFO** (по сроку годности), с автоматическим списанием из подходящих партий.
- **Материалы** — справочник: SKU, единицы, признак опасного вещества (MSDS),
  точка заказа.

Склад поддерживает зоны хранения (общая, климатическая, опасные вещества,
карантин) и ячейки.

### 6.3. ПРОИЗВОДСТВО (`/production`)

Управление производством и прослеживаемость партий. Hero-полиэдр — фиолетовый
пульсирующий октаэдр.

**Живая симуляция (реальное время):**
- 6 партий проходят 6 этапов техпроцесса: Подготовка пластины → Литография →
  Травление → Легирование → Тестирование → Упаковка.
- Каждые 10 секунд прогресс этапа растёт на 3–8%; при 100% — переход на следующий
  этап.
- С вероятностью ~5% возникает брак — партия останавливается, строка краснеет.
- При завершении всех этапов партия получает статус «Завершена», через 30 секунд
  появляется новая.
- Таблица: ID партии, текущий этап, прогресс-бар, статус, время старта/обновления.
- Кнопки «Остановить» / «Возобновить» / «Сбросить брак».
- **Клик по партии** → карточка с деталями + **SVG-анимация микрочипа**: рисуются
  корпус, контактные площадки и дорожки (`stroke-dasharray`), степень прорисовки
  отражает % изготовления; ключевые узлы пульсируют. Цвет дорожек — медный на
  тёмно-зелёной подложке.
- Фильтр по статусу партий.

**Работа с БД (классический MES):**
- **Заказы (Work Orders)** — список производственных заказов с маршрутами.
- **Партии (БД)** — реальные партии с lot/wafer ID, текущим шагом маршрута.
- **Новый WO** — создание заказа с маршрутной картой (этапы, рецептуры, целевые
  параметры, допуски). Регистрация фактических операций двигает партию по
  маршруту, статусы HOLD/PASS/REJECT/DONE.

### 6.4. ЛОГИСТИКА (`/logistics`)

Управление поставками и маршрутами. Hero-полиэдр — жёлтый кубооктаэдр.

- **3 KPI:** активных поставок, среднее время доставки, задержки / % вовремя.
- **Таблица активных поставок** (8 записей): ID, тип (входящая/исходящая),
  содержимое, маршрут «откуда → куда», статус (В пути / Ожидает / Доставлено),
  ETA. Каждые 60 секунд одна поставка «В пути» автоматически становится
  «Доставлено» с уведомлением.
- **SVG-карта маршрутов:** 5 точек (Склад сырья, Производство, Тест-лаборатория,
  Склад готовой продукции, Пункт отгрузки), соединённых анимированными
  пунктирными линиями (эффект движения потока). При наведении на точку —
  всплывающая подсказка.

### 6.5. ДЕРЕВО ПРОИЗВОДСТВА (`/tree`)

Интерактивная 3D-визуализация техпроцесса. Hero-акцент — бирюзовый.
Состоит из двух экранов с плавным переходом (fade + scale).

**Экран 1 — 3D-карусель выбора модели:**
- Круговая 3D-карусель из 8 карточек микрочипов (CSS `rotateY` + `translateZ`):
  серии Протон, Нейрон, Фотон, Кварц — у каждой свой цвет и уникальный SVG-силуэт
  (контроллер, процессор, FPGA, RF).
- Управление: перетаскивание мышью, прокрутка колёсиком, клик по боковой карточке
  (доводка в центр), инерция вращения.
- Центральная карточка яркая с подсветкой; боковые уменьшены, затемнены, размыты.
- При наведении на центральную — расширяется и показывает ТТХ (транзисторы, ядра,
  техпроцесс, область применения, число этапов, время цикла) и кнопку «Открыть
  дерево производства →».

**Экран 2 — 3D-дерево техпроцесса (Canvas):**
- Граф из 15 узлов-шестиугольников на 7 уровнях: снизу «Кремниевый слиток» →
  вверх «Готовый чип». Этапы: слиток → подготовка/осаждение → литография/
  травление/легирование → металлизация/планаризация/электротест → нарезка/
  die attach/разварка → финальный тест/корпусирование → готовый чип.
- Свободное вращение мышью (по X с ограничением ±60°, по Y без ограничений),
  зум колёсиком (0.5–2.0), инерция вращения.
- Рёбра с градиентом и **бегущими частицами** (имитация потока материалов).
- Корневой узел увеличен и пульсирует.
- **Наведение на узел** → тултип (описание, длительность, входные материалы,
  привязка к живой партии).
- **Клик по узлу** → выделение + выезжающая справа панель с подробностями: входные
  компоненты, результат этапа, оборудование, нормативное время, текущая партия.
- При первом открытии — анимация поэтапной «сборки» дерева от корня вниз.

### 6.6. ЧАТ (`/chat`)

Корпоративный чат сотрудников. Hero-полиэдр — оранжевый тетраэдр.

- Общий чат: сообщения с именем, ролью и временем; свои выделяются.
- Live-обновление каждые 3 секунды, slide-in анимация новых сообщений.
- **Системные сообщения** автоматически появляются при событиях симуляции:
  пополнение склада, обнаружение брака, завершение партии.
- Поле ввода с ротацией подсказок (placeholder), отправка по Enter.
- Сообщения хранятся в БД (таблица `chat_messages`).

### 6.7. АУДИТ-ЛОГ (`/audit`) — только admin/director

История действий. Hero-полиэдр — серебристый додекаэдр.

- **Журнал БД** — все действия пользователей (вход, приёмка, выдача, создание WO,
  операции и т.д.) с привязкой к времени, объекту и IP.
- **События системы (live)** — лента событий симуляции с цветовой маркировкой:
  info (голубой), success (зелёный), warning (жёлтый), error (красный).
- Фильтр по типу события.

## 7. СКВОЗНЫЕ ВИЗУАЛЬНЫЕ ЭФФЕКТЫ (на всех страницах)

Реализованы в `fx.js` и подключены глобально через `base.html`:

- **Левая боковая панель «Цепь данных»** — вертикальная линия с поднимающимися
  светящимися частицами; ромбы-узлы вспыхивают при прохождении частиц; частицы
  ускоряются во время активных событий; зелёный индикатор «система активна».
- **Правая боковая панель «Код потока»** — Matrix-стиль из hex/бинарных символов,
  случайные вспышки акцентным цветом, вертикальный водяной знак с названием
  вкладки.
- **Фоновая точечная сетка** — медленно пульсирует, случайная точка вспыхивает
  каждые 5 секунд.
- **Курсор-трейл** — шлейф из 6 точек, плавно догоняющих курсор.
- Цвет частиц и трейла соответствует акцентному цвету текущей вкладки.

**3D-полиэдры** (`polyhedron.js`) — у каждой вкладки свой вращающийся каркасный
многогранник, отрисованный на Canvas (матрицы поворота Rx·Ry + перспективная
проекция): икосаэдр (дашборд), куб (склад), октаэдр (производство), кубооктаэдр
(логистика), тетраэдр (чат), додекаэдр (аудит).

**Клиентская симуляция** (`simulation.js`) — единый модуль, моделирующий
производство и склад в реальном времени; состояние разделяется между вкладками
через `localStorage`; рассылает события (`tick`, `replenish`, `defect`,
`complete`) подписчикам; управляет цифровыми часами и toast-уведомлениями.
